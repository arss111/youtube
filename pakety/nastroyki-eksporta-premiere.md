# Настройки экспорта Premiere Pro для YouTube (игровой контент, 60 fps)

## Твои текущие настройки — нормально?
**Да, по качеству всё в порядке.** H.264, 2560×1440, 60 fps, Rec. 709 и CBR 80 Мбит/с — картинку это не портит.
- 80 Мбит/с — с большим запасом: YouTube для 1440p60 советует от 24 Мбит/с.
- Для игр запас битрейта не вредит. Быстрое движение, трава, взрывы и частицы сжимаются хуже всего, и чем чище исходник, тем лучше их пережмёт YouTube. Но выше ~40–50 Мбит/с для 1440p разница почти незаметна.
- Цена запаса — только размер файла (~20 ГБ) и время загрузки.

## Что реально повышает качество на YouTube (по силе эффекта)

1. **Качество записи в OBS.** Если исходник записан с низким битрейтом, экспорт в 80 Мбит/с его не улучшит: потерянные детали не вернуть. Для записи ставь высокое качество (например, CQP/CRF 16–20 или 50+ Мбит/с для 1440p60).
2. **Выгружать в 4K (2160p).** YouTube выдаёт 4K-видео заметно больший битрейт и лучший кодек, причём выигрыш есть даже у зрителей, которые смотрят в 1440p и 1080p. Для игрового контента это самый заметный приём. Минус — экспорт дольше, файл больше.
3. **Профиль «Высокий» (High) вместо «Основного».** Тот же битрейт — чуть лучше картинка. Сними галочку справа от поля, чтобы его поменять.
4. **Интервал ключевых кадров = 30** (половина от 60 fps), как рекомендует YouTube.
5. **Публиковать только после обработки HD/4K.** Загружать заранее и ставить «Запланировать». Иначе первые зрители видят мыло, пока YouTube доделывает высокие разрешения.

## Вариант А — максимальное качество (4K)
| Параметр | Значение |
|---|---|
| Размер кадра | **3840×2160** (снять галочку «как у источника») |
| Частота кадров | 60 |
| Профиль / уровень | Высокий / 5.2 |
| Рендеринг при максимальной глубине + наилучшее качество | **Включить** (важно при увеличении) |
| Кодирование | VBR, 2 прохода (или 1 проход с аппаратным ускорением) |
| Целевой / максимальный битрейт | **60 / 80 Мбит/с** |
| Ключевые кадры | 30 |
| Размер файла на ~21 мин | ~9–12 ГБ |

## Вариант Б — твой 1440p, но эффективнее
| Параметр | Значение |
|---|---|
| Размер кадра | 2560×1440 |
| Профиль / уровень | Высокий / 5.1 |
| Кодирование | CBR 80 можно оставить. Или VBR: целевой 40, максимальный 60 Мбит/с — меньше файл без заметной потери |
| Ключевые кадры | 30 |
| Размер файла на ~21 мин | ~6–12 ГБ |

## Для обоих вариантов
- **Аудио:** AAC, 48 000 Гц, стерео, 320 кбит/с.
- **Громкость:** «Эффекты» → «Нормализация громкости» → ITU BS.1770-3, **−14 LUFS**, истинный пик **−1 dBTP**. Сейчас видео тихое (−23 LUFS).
- HDR не трогать, метаданные HDR10 выключены, Rec. 709.
- Аппаратное ускорение можно оставить. На таких битрейтах разница с программным кодированием незаметна.

## Лёгкая версия, чтобы прислать мне на проверку
1280×720, 30 fps, VBR 3 Мбит/с, аудио AAC 128 кбит/с → ~400–500 МБ на 20 минут. Загружать в Releases на GitHub.
